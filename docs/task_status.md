## 二、系统性问题：角色死亡处理

这是目前最普遍、也最影响体验的缺口 —— 真正处理了「复活之后怎么办」的只有世界首领（分段续跑）、域外迷窟（原地继续）和自动任务的挂机阶段，其余任务全靠全局「整任务重跑」。

### 2.1 现在的机制

`tasks/GlobalGame/global_game.py` 里，每次 `screenshot()` 都会经过死亡检测：

1. `handle_death()` 匹配到死亡弹窗（`I_DEATH_DIALOG`）→ `revive()` 点「返回村子」（点击区域跟随弹窗实际位置偏移）；
2. `rerun_task()` → `save_task_record()` 存进度 → `config.task_call(当前任务)` 把当前任务设为「立即重跑」→ 置 `_rerun_requested = True` → `raise TaskEnd`；
3. 任务 `finally` 里调 `set_next_run()` 时，`BaseTask.set_next_run` 检测到 `_rerun_requested` 就跳过排期，保住「立即重跑」。

### 2.2 为什么不对

- **重跑 = 整任务从头开始**：答题本局作废（已答的题面全部丢失）、仙府已消耗的仙石与当前选关丢失、竞技/斗仙阁的计数可能重复或错乱；
- **任务的 `finally` 会反噬**：多数任务无条件 `set_next_run(success=True)`，会把「立即重跑」覆盖掉 —— 域外迷窟的注释里记了实测：15:58 死亡后被排到第二天 10:27，任务当天直接结束；
- **进度保存形同虚设**：`save_task_record()` 默认返回 `{}`，只有世界首领真正实现了 `save_task_record` / `load_task_record`。

### 2.3 计划

`rerun_task` 后续会移除（连带 `_rerun_requested` 和 `BaseTask.set_next_run` 里的跳过分支）：

1. 全局只负责「检测死亡 + 点复活」，不再决定任务排期；
2. 每个任务自己覆盖 `handle_death()`，负责复活之后的续跑 —— 回到原阶段 / 回到基准点 / 重新进图，由任务自己决定；
3. 需要跨进程保留进度时，仍用 `save_task_record` / `load_task_record` 这对钩子。

## 三、任务详解

### 1. 重启登录 `Restart` ✅ 完整可用

- **定位**：所有任务的依赖项。游戏不在线时由调度拉起；也是 `GameStuckError` / `GamePageUnknownError` 的统一恢复手段。
- **客户端分派**：`get_client()` 按 `PackageName` 选择登录流程 —— 小七版走 `RestartX7`，官方版走 `RestartOfficial`（继承小七流程，仅覆盖账号页/区服页）。
- **小七版流程**：开屏登录页 → 选服务器（先看「我的服务器」的上次登录区服，没有则切「全部服务器」按 93→92→… 降序翻页查找）→ 账号选择（OCR 账号名，识别区域即点击区域）→ 角色选择（OCR 角色名，点对应侧的「登录角色」）→ 主界面 → 清弹窗。
- **官方版流程**：通过 `device.u2` 定位 `EditText` 写入账号密码，用原生「确定」按钮提交，避免软键盘/错误提示改变坐标；密码输入页截图在进入 `screenshot_deque` 前先涂黑，防止错误日志带出明文。
- **兜底**：登录失败重试 2 次；累计超过 `login_timeout`（默认 240s）按业务失败处理（推送 + `TaskFailed`，交给「处理部分异常」决定是否继续）；账号密码错误直接 `RequestHumanTakeover`。
- **维护窗口**：周二 07:30–08:30 判定为服务器维护，`delay_pending_tasks()` 把待办任务统一推到 09:00。
- **缺口**：无。这是目前唯一按正常流程完整跑通的任务。

### 2. 每日答题 `Quiz` ⚠️

- **触发**：每天一次，结束后排到次日 09:00。从背包使用「趣味答题券」进入答题界面。
- **单题流程**（每题硬预算 `question_time_limit` 默认 20s）：
  1. 本地 OCR 读题干 + 三个选项；
  2. 题库按「题干 + 选项」双键匹配，命中且已验证则直接用题库答案；
  3. 未命中则交 DeepSeek（默认 `deepseek-flash`）看图作答；剩余预算不够就不问，直接兜底；
  4. 点击选项 → 等「回答正确/回答错误」贴纸 → 判定对错；
  5. 回写题库：答对转正，答错记录错误选项形成排除表。
- **题库同步**：答题前从 git 交换仓库合并其它设备学到的题，答题后推送本机新增。
- **缺口**：
  1. **缺角色死亡处理** —— 任务没有覆盖 `handle_death`，答题中途阵亡会走全局死亡逻辑（复活 + 整任务重跑），本局已答的题面/进度全部丢失，只能从头再答一遍。
  2. **缺答题券不可用的处理** —— `enter_quiz_by_ticket()` 返回 False 时只打一条 `答题券不可用（可能今天已经答过），跳过本次答题` 的 warning，既没有区分「今天已答过 / 背包里没有券 / 点不到立即使用」，也不推送提醒，实际就是静默跳过一天。
  3. 只支持 A/B/C 三个选项（`OPTION_CLICKS` 固定三项），四选项题不适用。
  4. 未配置 `api_key`（且环境变量也没有）时，未知题只能走兜底，正确率取决于题库覆盖率。

### 3. 参与战车 `WarChariot` ⚠️

- **触发**：每天 `start_time`（默认 20:00）开放，提前 `advance_time`（默认 5 分钟）把游戏准备到主页面。
- **已实现**：到点后每 `check_interval`（2s）识别一次文字区域 → 命中 `keyword`（默认「仙盟战车」）→ 在按钮区域找「接受」并点击 → 校验当前地图已变成战车地图 → 等 2s 关闭游戏 → 离线 `offline_time`（默认 5 分钟）→ 重启游戏登录回主页面。
- **缺口**：
  1. **进入战车后直接退出** —— 只做到「点接受 + 校验进了战车地图 + 关游戏挂离线时长」，战车内的正常流程（跟随战车、战斗、结算/领奖）完全没有实现；
  2. 按设计意图应该按游戏实际玩法把战车这一段走完，再决定何时下线，而不是进图就关游戏；
  3. **缺角色死亡续跑** —— 等待开放/参与过程中阵亡会走全局「复活 + 整任务重跑」，回到准备阶段重来。

### 4. 银贝礼盒 `SilverGiftBox` ⚠️

- **触发**：每天一次，走标准成功间隔 + 服务端刷新时间排期。
- **已实现**：准备主页面 → 传送 `relay_location`（默认牧野）→ 开小地图 → 右侧 NPC 列表滑找 `npc_name`（默认宝具商人）→ 自动寻路 + 坐标稳定判定到达 → 对话点 `shop_option`（默认「玲珑换宝」）→ 找到并校验银贝礼盒 → 数量调到最大 → 购买确认 → 回主页面。
- **缺口**：
  1. **缺「已购买礼盒」的判断** —— 没有检查今天是否已经买过/是否已达购买上限，重复运行会再次走到购买流程（对已售罄的状态没有识别与正常收尾）；
  2. 任一步失败只告警，靠 `finally` 重排，不会重新尝试整条链路；
  3. **缺角色死亡续跑** —— 走到 NPC / 买货过程中阵亡会整任务重跑（见「二、系统性问题」）。

### 5. 自动任务 `AutoTask` ⚠️（缺口待核对）

- **定位**：把任务特权页里的日常一次性清完（修真/金钱/技能/经验/游历/坐骑/仙盟/麒麟/玲珑每日）。
- **已实现**：队伍页确保非组队 → 任务特权页检查特权（「激活」= 过期，推送并按任务失败结束）→ OCR 读 10 个任务进度（一屏 7 行、最多滚 3 屏）→ 选下一个（加量优先，循环任务不参选）→ 加量页调卡 → 进详情点「自动」→ 回主页按 `running_check_interval`（30s）查完成 → 回特权页重读，直到除循环任务外全满。
- **防护**：同一任务进度连续 3 轮不动则推送 + `TaskFailed`；`non_blocking` 勾选后，其它任务到期会中断自动任务让路，10 分钟后恢复。
- **加量**：修真/金钱/技能/经验/坐骑/仙盟 6 个任务可分别选 3 倍/5 倍；卡不足时按 `continue_without_bonus` 决定「不带卡继续」还是「通知并失败」。
- **缺口**：
  1. 本轮核对未列出具体缺失环节，状态暂按「部分实现」记，**待逐环节核对后补充**；
  2. 已知风险：`TASK_TOTALS` 硬编码 10 个任务的最大进度（OCR 只读已做数），**游戏改总数时必须同步改** `script_task.py:70`；
  3. **复活续跑只覆盖一半** —— 只有「回主页挂机等自动完成」阶段不重跑，其余阶段阵亡仍走全局整任务重跑，进度要回特权页重读、加量卡可能重复调整。

### 6. 世界首领 `WorldBoss` ⚠️

- **触发**：按 5 个首领的固定场次（`BOSS_LIST`：蛮锤 09/11/13、无情 10/12/19、巨镰 15/17/19、斧王 14/18/22、蝎王 21），提前 `advance_time`（默认 5 分钟）出发。
- **已实现**：确认地图（不在首领地图先传送）→ 活动-世界首领页点「寻」→ 轮询坐标判定到达（10s 无变化重新点「寻」）→ 收起菜单 → 点「目标」锁定（OCR 目标名，2x/3x 双尺度取置信度高者）→ 按任务预设的技能队列攻击。
- **结束判定**：轮询聊天栏「结束模板」，分数达阈值直接判定，否则 OCR 二次确认 → 等「首领归属奖」弹窗 → 收尾。

- **缺口（代码中已有 TODO）**：
  1. **天师的幻影未接入** —— 全服 boss（12:00/22:00），属全服地图的特殊 boss，需先确认专属地图与机制，再补进 `BOSS_LIST` 和配置时间（`tasks/WorldBoss/script_task.py:19`）；
  2. **双 boss 期间被其他玩家攻击未处理** —— 受击可能打断回主页面/地图传送/「寻」的自动寻路，目前没有受击检测与重试（`tasks/WorldBoss/script_task.py:671`）。

### 7. 同服竞技 `Arena` ⚠️

- **触发**：仅 12:00–22:00 运行；每天最多 `count` 次（默认 10），勾选 `use_activity` 后改为「活动-活跃页里的同服竞技完成即收工」。
- **已实现**：挑战-战场页 → 确认右侧选中「同服竞技」（左侧出现「2人角斗」）→ 双击报名 → 「确定」→ 回主页每 2s 轮询匹配弹窗（超时 `match_timeout`，默认 20 分钟）→ 匹配成功点「确定」→ 2s 后**重启游戏**（顺带清掉排队状态）→ 计数 +1 → 未达次数立刻开下一局。
- **缺口**：
  1. **缺正常游玩逻辑** —— 点完「确定」参战就重启游戏，没有进入对局、没有战斗、没有结算与领奖；
  2. 因为不参与对局，胜负与奖励完全依赖游戏自动战斗，任务侧的「完成一局」只等于「报名成功并参战」。
  3. 活跃度模式下等待匹配时会为高优先级任务让路（重启 + 5 分钟后重排），这部分是可用的；
  4. **缺角色死亡续跑** —— 报名/等待匹配时阵亡走全局整任务重跑，`completed` 计数与排队状态都不受控（见「二、系统性问题」）。

### 8. 跨服竞技 `CrossArena` ⚠️

- **触发**：仅 13:00–14:00、17:00–18:00 两个时段；次数与活跃度逻辑同 `Arena`。
- **已实现**：流程与同服竞技一致，区别是确认右侧选中「跨服竞技」、左侧出现「2人跨服」；当天两个时段都过了把 `completed` 清零并排到次日 13:00。
- **缺口**：与 `Arena` 相同 —— **只到报名→参战就重启，缺正常对局与结算**；另外同样缺角色死亡续跑，阵亡后整任务重跑。

### 9. 上古狩猎 `AncientHunt` ⚠️

- **触发**：开放时段默认 12:35–12:45、17:05–17:15（`open_times`），提前 `advance_time`（3 分钟）准备主页面。
- **已实现**：查活动-活跃页的「上古狩猎」是否已完成（参与过就不再进）→ 等开放时间 → 传送到牧野落点 → 收右上角菜单 → 点「目标」锁定「上古狩猎神」（读到目标名并匹配才算成功）→ 点攻击键 → 「进入上古狩猎场」→ 等 `enter_wait`（2s）**重启游戏** → 排到次日。
- **缺口**：
  1. **只完成了「进入」** —— 进入狩猎场后就重启退出，场内的正常玩法（打怪、坚持时长、结算奖励）没有实现；
  2. 是否真正完成活动只能靠活动-活跃页的完成度间接判断；
  3. **缺角色死亡续跑** —— 准备/进图前后阵亡会整任务重跑，可能重复消耗当天的参与机会。

### 10. 仙府九重天 `XianfuJiuchongtian` ⚠️

- **触发**：仙石（每 30 分钟 +1，上限 40）达到 `stone_threshold` 才开工；不够就按 `(阈值 - 当前) × 30 分钟` 排下一次，仙石已满 1 分钟后重试，读不到仙石 5 分钟后重试。
- **打法**：按 `stage`（1 南极 / 2 北极 / 3 东极 / 4 西极）打各大关的第 N 小关；默认先扫背包统计四种碎片数量，按缺失的号从大到小选大关，`fixed_daguan`（1–4）可直接指定大关并跳过统计。
- **单局**：选大关 → 选小关 → 开始挑战 → 进图开小地图点战斗点自动寻路 → 收菜单锁怪（右下角必须是「攻击」）→ 技能队列释放 → 目标丢失/奖励面板出现即停 → 翻牌领奖 → 更新碎片数量 → 循环直到仙石 < 4（每局消耗 4）或达到 `max_battles`。
- **缺口**：
  1. **缺角色死亡复活处理** —— 任务没有覆盖 `handle_death`，战斗中途阵亡会走全局死亡重跑，整任务从头开始（本局已消耗的仙石、当前选关状态都会丢），而不是「复活后回到本关继续打」；
  2. 目标丢失后回到仙府页仍无奖励面板时按「本关未通过」处理，只推送通知并继续下一轮，需要人工确认（`script_task.py:628`）。

### 11. 域外迷窟 `YuwaiMimang` ⚠️

- **触发**：怪物刷新时段默认 10:30–11:30、15:30–16:30（`monster_times`），提前 3 分钟准备；不在时段内直接排下一场。
- **已实现**：传送沼泽 → 开小地图 → NPC 列表滑找「迷窟守卫」→ 自动寻路 → 对话「进入域外迷窟」→ 校验地图与坐标 → 走到基准坐标 `battle_coord`（默认 304,76）→ 循环打怪 → 被怪推离自动回位 → 每 20 分钟原地修理装备 → 时段结束离开并排下一场。
- **死亡**：覆盖了 `handle_death`，在窟内原地复活继续打，不重跑任务 —— 与世界首领并列，是目前仅有的两个自行处理复活的任务之一；全局 `rerun_task` 移除后本任务不受影响。
- **缺口**：
  1. **战斗逻辑没有跟进新版** —— 仍是早期的 `click_attacks_once()`：点一次「目标」+ 普攻/技能 1/技能 3 各点一遍、再停一下的固定套路；没有接入 `tasks/Battle` 的技能栏识别、冷却判定与预设队列（世界首领/仙府/战斗试打已在用），所以换职业、技能位不同或技能未解锁时会点空/点错；
  2. 只在刷怪时段有怪，属游戏机制，不算缺口。

### 12. 斗仙阁 `DouXianGe` ⚠️

- **触发**：每天；`challenge_count` 为 0 时把剩余次数全部打完，否则按配置次数打。
- **已实现**：结算重置期（周日 23:00 – 周一 12:00，页面为空）直接排到下周一 12:00 后 → 进斗仙阁页 → 读「今日剩余次数」+「特权额外次数」→ 循环：点列表第一个「挑战」→ 等进入斗仙阁战斗地图 → **重启游戏**回主页面 → 计数 +1。
- **缺口**：
  1. **进图即重启** —— 没有走正常对局流程（战斗、结算、翻牌/领奖），「挑战成功」只等于「成功进入了战斗地图」；
  2. 因此次数统计与真实战果无关，失败局也会被计为已完成；
  3. **缺角色死亡续跑** —— 对局/切页时阵亡会整任务重跑，计数从 0 重新累加（见「二、系统性问题」）。

### 13. 副本玩法 `Dungeon` 🚧 未开始

- **现状**：只有 `common.py`（`DungeonBase`：`prepare()` / `back_to_main()`）、`script_task.py`（按 `DUNGEONS` 登记表挑副本逐个执行）、`dungeons/` 空目录与 `dungeon_interval` 配置项；`DUNGEONS` 为空，跑起来只打印「没有启用任何副本，本次跳过」。
- **缺口**：**没有任何具体副本**，等于一个空的玩法容器。扩展方式：在 `dungeons/` 新建继承 `DungeonBase` 的类并实现 `run()` → `config.py` 加开关 → `script_task.py` 的 `DUNGEONS` 登记。

- **继承自 OAS 的组件未清理**：`tasks/Component/{Buy,GeneralBattle,GeneralBuff,GeneralInvite,GeneralRoom,Summon}`、`tasks/Utils` 等只被彼此引用，没有任何任务使用；`tasks/GameUi/pages/page.py` 的 `random_click()` 还依赖 `GeneralBattleAssets.C_REWARD_*`，清理时一并删掉该函数即可。

## 六、新增任务的接入步骤

1. 建目录 `tasks/<TaskName>/`，至少包含 `config.py`、`script_task.py`、`assets.py`、`res/`；
2. `config.py` 里定义 `Scheduler` + 任务参数，参数类与任务目录同名；
3. `script_task.py` 里实现 `ScriptTask`（继承 `GameUi` + `XxxAssets`），`run()` 结束前必须 `set_next_run`（建议放 `finally`），再 `raise TaskEnd`；
4. 在 `module/config/config_model.py` 注册字段，在 `module/config/config_menu.py` 加入对应分组，在 `module/config/config_manual.py` 的 `SCHEDULER_PRIORITY` 里排优先级；
5. 素材用标注工具录制（Web 界面 `/tool/annotator`），规则 JSON 存 `res/`，`assets.py` 由 `dev_tools/assets_extract.py` 生成；
6. 需要中文名/说明时补 `assets/i18n/zh-CN.json`；
7. 完成后更新本文档的「状态总览」与对应小节。

详细规范见 [mcp/task_dev_guide.md](mcp/task_dev_guide.md)。
