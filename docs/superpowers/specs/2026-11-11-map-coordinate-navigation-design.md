# 小地图坐标寻路模块设计

**状态：** 设计已确认，待用户审阅

**日期：** 2026-11-11

## 背景

游戏小地图可以点击地图位置并自动寻路。地图内容视口会随地图大小改变，单一固定屏幕矩形不能覆盖所有地图；地图本身也有不可达位置。当前 `tasks/GameUi/world/map.py` 将 `MAP_CONTENT_REGION` 和箭头检测区域写成固定坐标，不能直接用于所有地图。

已知边框色由取色工具报告为 `0x180C00`；在本项目 RGB 截图中对应 `(0,12,24)`。颜色边界可用于识别地图弹窗的内容框和地图/NPC 栏分隔线。沼泽、域外灵岛的样本显示每地图需要自己的坐标变换，四个视口角落则需要分别记录地图平移偏移。

## 目标

- 在独立目录中封装从地图坐标到小地图点击的完整寻路流程。
- 自动检测地图视口，不要求 JSON 手工填写视口原点或矩形。
- 按地图名称保存可达样本；每张地图分别标定左上、右上、左下、右下四个视口状态。
- 到达目标坐标后返回实际位置；不可达、数据缺失或识别失败时记录明确日志并走任务失败流程。

## 非目标

- 不探索或自动学习整张地图的可达区域。
- 不保证游戏中不可达的位置能被走到，也不对偏差点自动盲点重试。
- 不自动确认 NPC 对话、购买或其他弹窗。

## 模块边界

新增包：`tasks/GameUi/world/map_coordinate/`

- `viewport.py`：从当前截图识别小地图内容视口及检测置信度；根据模板/视口边缘判定当前四角视图。
- `calibration.py`：读取并校验按地图名组织的样本，拟合地图内像素比例及各角视图的平移偏移。
- `navigator.py`：执行打开小地图、选择视图、转换坐标、点击、关闭小地图和到达检查。
- `maps.json`：地图名及四角的手工样本数据。

由 `GameUi` 门面混入新导航能力，任务调用 `map_go_to_coordinate(x, y, ...)`。复用现有的小地图开关、视口平移和地图坐标读取能力；只在必要处增加相对视口的箭头/边界识别，不影响既有地图传送与摇杆移动接口。

## 视口识别

1. 截图固定为项目要求的 `1280×720`。按边框色建立颜色掩码；目标色值按 RGB 截图读取为 `(0,12,24)`。
2. 在地图弹窗范围内识别边框连续线、地图图片与右侧 NPC 栏的分隔线，输出左侧地图内容矩形，不把弹窗边框或 NPC 栏算入地图视口。
3. 检查矩形尺寸、边线连续性和箭头状态，生成检测置信度。置信度不足时不点击，按业务失败处理。
4. 用四边箭头识别当前视口角落；必要时调用平移能力到选定角落，再重新检测视口。

边框检测用例至少覆盖沼泽、域外灵岛和建木城的截图。已测量的示例视口包括：沼泽约 `(161,105)`、域外灵岛用户估值约 `(219,103)`、建木城颜色边界内侧约 `(262,105)`；实际值以检测结果为准。

## 地图样本与坐标拟合

JSON 按游戏地图名称及四个视口状态组织，样本使用用户要求的整屏像素坐标和真实到达坐标：

```json
{
  "maps": {
    "沼泽": {
      "views": {
        "top_left": [
          {"screen": [542, 208], "coord": [223, 61]}
        ],
        "top_right": [],
        "bottom_left": [],
        "bottom_right": []
      }
    }
  }
}
```

所有样本必须是在对应角视口下点击**可达位置**并等待稳定后读取的坐标。JSON 的 `screen` 保持整屏绝对像素；运行时用自动识别的视口左上角将样本换算为视口内偏移，不要求人工填写原点。每张地图拟合自己的 X/Y 像素比例，四个角分别拟合内容平移偏移。样本与运行时必须使用相同的 `1280×720` 地图 UI 布局；若样本换算后落在视口之外或残差超过阈值，标定无效并要求补录，而不是猜测。

建议左上视图至少录 4 个分布较开的样本以确定和验证比例；其余三个视图至少各有一个锚点，最好各有两个。样本拟合检查每轴跨度、重复/退化点和最大残差。屏幕坐标以对应地图视口左上状态、固定分辨率 `1280×720` 为准。

## 寻路流程与失败处理

1. 读取当前地图名称和坐标；允许调用方显式传地图名。地图没有 JSON 标定数据时立即失败，不套用其他地图参数。
2. 打开小地图并识别视口。对四个已标定视图分别预测目标像素，选择目标落在地图内容区内的视图；若需要则平移至该角，再确认视图状态。
3. 仅点击一次目标像素，关闭小地图，轮询右上角地图坐标。
4. 每轴误差不超过默认容差 1 格即返回实际到达坐标；若起点已在容差内则不点击。
5. 点击后每秒读取一次坐标。连续 5 秒没有坐标进展且仍在容差外，或角色位置连续稳定 3 秒但仍超出容差，即判定不可达；总超时默认 60 秒。以上等待值可由调用方覆盖。
6. 不可达、超时、目标不在四角校准覆盖范围、地图/视口/标定数据缺失时：记录目标和实际坐标，日志说明“坐标不可达”或具体失败原因，并抛 `TaskFailed`。现有 `script.py` 将其作为任务业务失败记录，不触发游戏重启。
7. 遇到 NPC 对话等弹窗不自动确认；寻路失败或页面被弹窗阻断时不继续盲点。

用户确认当前地图四角视图能够覆盖整张地图。模块仍会检查目标是否落入已标定四角视图的覆盖并留安全边距；若后续地图存在覆盖缺口，则必须补录中间视图样本，否则失败关闭。

## 测试

- 视口识别：基于色边框和地图/NPC 分隔线的单元测试，验证不同视口尺寸、颜色容差、误检/低置信度处理。
- 拟合：使用已提供的沼泽和域外灵岛样本验证每图比例、四视图偏移、样本不足和高残差拒绝。
- 寻路编排：使用假设备测试目标视图选择、到达、不可达、无进展、超时、缺地图数据和视口检测失败；不可达必须日志并抛 `TaskFailed`。
- 真机验证：在有完整四角样本的地图上验证目标点转换、视图切换、坐标到达及不可达失败流程。真机测试不作为自动 CI 测试。
