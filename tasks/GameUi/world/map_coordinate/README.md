# 小地图坐标寻路

`GameUi.map_go_to_coordinate(x, y)` 按当前地图的小地图数据点选坐标，让游戏自动寻路；成功返回稳定读回的 `(地图名, x, y)`，不可达或超出已标定/估算范围时记录原因并抛 `TaskFailed`。

## 地图类型与视图

按小地图能否平移，分三种，录入的视图名不同：

| 地图类型 | 判断 | 需要录入的视图 |
|---|---|---|
| 四角大地图 | 左右、上下箭头都会随拖动出现/消失 | `top_left`、`top_right`、`bottom_left`、`bottom_right` |
| 单轴两角地图 | 只有左右箭头，或只有上下箭头 | 横向可滚：`top_left` + `top_right`；纵向可滚：`top_left` + `bottom_left` |
| 固定小地图 | 没有箭头，拖动地图不动 | 只录 `top_left` |

- 主视图（默认 `top_left`；若左上没有样本，自动取样本最多的视图）至少 4 个样本，且 X/Y 坐标跨度都要 ≥20 格。
- 其他视图至少 1 个样本（建议 2 个以上），用于拟合该角的平移偏移。
- 单轴地图不可滚的那一轴是固定的：比如纵向可滚时，`top_left` 和 `bottom_left` 的 X 偏移应当相同。另外两个角名与这两端等价，不需要重复录。
- 固定小地图整张图都在视口内，`map_pan_to_corner('top_left')` 检测不到箭头时会直接返回成功，不会拖动。

## 地图数据录入

数据放在同目录的 `maps.json`，以 OCR 使用的地图名为键。每个视口角 (`top_left`、`top_right`、`bottom_left`、`bottom_right`) 下录入多组可达样本：

```json
{
  "地图名": {
    "views": {
      "top_left": [
        {"screen": [542, 208], "coord": [223, 61]},
        {"screen": [750, 239], "coord": [347, 79]}
      ],
      "top_right": [
        {"screen": [900, 220], "coord": [430, 70]}
      ]
    }
  }
}
```

- `screen`：1280×720 全屏截图上的实际点击像素，格式 `[x, y]`。
- `coord`：点选并等待人物稳定后，从游戏坐标读回的真实坐标，格式 `[x, y]`，不是预期目标。
- 录样本前先把地图拖到 JSON 对应的视口角，样本点必须可达；点击后没有移动的点不要作为标定样本。
- 主视图至少录 4 个分布较开的点；其他角至少录 1 个锚点，建议 2 个以上。模块自动识别视口边框并归一化整屏像素，不需要手填视口原点。
- 样本拟合包含自动截距；若目标坐标精确匹配样本，会直接复用该样本的点击像素。其他坐标会检查预测像素邻域的整数取整误差。
- 如果某角未录入，落在该角才可覆盖范围内的目标会安全失败，不会套用其他地图或其他角的数据。

录入步骤：

1. 打开小地图，确认该地图的滚动轴（四边箭头）；四角地图逐角录入，单轴地图只录两个端点，固定小地图只录一个视图。
2. 用 `map_pan_to_corner('top_left')` 等把地图拖到目标角。
3. 在视口内点一个可达点，等角色稳定后读回真实坐标；`screen` 填点击时的整屏像素，`coord` 填读回的坐标（不是点击时想去的坐标）。
4. 主视图录 4 个以上分布开、两轴跨度都 ≥20 格的点；其他视图各录 1~2 个锚点。
5. 用 OCR 读出的地图名（与 `map_move_read_pos()[0]` 一致）作为 JSON 的键。

运行时 `MapCalibration.fit` 会校验：主视图样本不足 4 个、任一轴坐标跨度 <20 格、或回投残差 >2.5 格时直接拒绝该地图的标定并报错。

自动检测依据取色工具值 `0x180C00`（在 RGB 截图中的通道值为 `(0,12,24)`），并利用地图与 NPC 列表间的分隔线裁出地图内容区。设备分辨率需保持 1280×720。

## 未标定地图（估算）

`maps.json` 里完全没有记录的地图不再直接失败，而是走估算：

- 视口左上角视为地图坐标 `(0,0)`，比例固定 `1.69 像素/格`（由沼泽、域外灵岛的左上样本拟合值取均值）。
- 固定平移到 `top_left` 视图，仍然执行 8px 边界检查；目标超出左上视图范围时安全失败，不会夹到边缘。
- 估算没有其他三个角的偏移数据，所以只覆盖左上视图。
- 到达校验失败时，日志会提示「地图未标定，估算比例可能造成偏移」。
- 已有标定数据的地图（即使目标超出已录角视图）仍按原有逻辑失败，不会回退到估算。

估算只适合应急；长期使用建议补录至少 4 个左上样本，并把该地图加入 `maps.json`。

## 调用示例

```python
actual = self.map_go_to_coordinate(350, 158)
```

默认读取当前地图；也可传 `map_name`、`timeout`、`tolerance`。角色没有移动、停在容差外或超出已标定/估算范围时会抛 `TaskFailed`，由调度器按任务业务失败处理。小地图点选不会自动确认 NPC 对话或其他弹窗。
